Auto-generated by nix run .#ext-explorer — do not hand-edit. Two data sources are stitched together. (1) The major/minor timeline is the append-only log in nix/ext/version-history.json: each row freezes the full extension state as of the commit right before nix/config.nix's postgres/orioledb version fields next changed. The generator appends a new row automatically whenever it runs on a commit where those fields changed since the previous commit — CI enforces that this file and this page are always regenerated together. (2) For each minor, the extension list shown is exactly the row's frozen nix/ext/versions.json snapshot (plus supautils/orioledb, which are pinned directly in their own .nix file rather than via versions.json) — every version listed for a given minor is what the "full" build variant places on disk simultaneously for that snapshot, not a cross-snapshot history; the highest one is the default active version. Rows marked inferred predate this repo's versions.json migration — that extension's version was read directly from the hardcoded version = "…" field in its own nix/ext/<name>.nix at the time, with per-major applicability inferred from which extension list (ourExtensions / dbExtensions17 / orioledbExtensions) included that file at that commit.
